# Benchmark results

## Current-state report

`benchmarks/results/current.md` is regenerated by every benchmark run. It has a
machine and environment header, then the sections:

- `Feature matrix` states, for each tool, whether it builds the package, tests,
  clippy, docs, and doctests, and whether it works per crate or per workspace;
- `Process` describes the seed, prepare, measure, and repeat loop, the
  scenario variants, and the fixture groups;
- `Test cases` lists each scenario with its variants and description;
- `Summary` has one sub-section per fixture group. Each sub-section states the
  per-builder check coverage and a ratio matrix with one row per scenario and
  one column per builder, with Bloomery's absolute mean time; and
- `Details` has one sub-section per fixture group listing builder, scenario,
  sample count, mean, standard deviation, minimum, maximum, and ratio to
  Bloomery for every measurement.

Check numbers for tools that do not run a full suite carry a marker: `*` when
`check` runs tests only and `**` when it builds the package only. Bloomery and
crane run test, clippy, and doc suites and carry no marker.

Each fixture summary repeats its group description. The check-coverage note
calls out builders whose `check` variant is only a package build (cargo2nix and crate2nix) and builders whose suite omits clippy or
documentation, so the check timings are read with the right scope.

The header records the machine the run used (CPU model, physical and logical
core counts, total memory, and kernel), the target system, nixpkgs revision,
Rust toolchain version, builder input revisions, `--max-jobs`, `--cores`, and the
run date.

## History log

`benchmarks/results/history.json` accumulates one entry per run and preserves
prior entries. Each entry carries the run timestamp, machine identity and
memory, target system, toolchain and input revisions, parallelism, per-builder
and per-scenario samples, and summary statistics.

The file is an object with a `runs` array; appending a run never rewrites
earlier entries.

## Machine identity

Both files name the machine the benchmark ran on. The machine record includes
CPU model, physical core count, logical core count, and total memory. Runs from
different machines remain distinguishable in the history.
